# Rig and splash menu — 8 September 2026

The rig's pure geometry factory is now client/rig-model.ts. OVERLAND owns the shared physical footprint. main.ts retains simulation, bodywork shader and renderer state. Classic and Ranger use the same contact geometry; neither model nor its equipment knows about campaign state. Equipment choices are Expedition, Light and Service. Ranger adds a stepped utility canopy, lower body slab, mirrors and wheel shoulder detail. These are first-pass geometry improvements awaiting visual judgement on a WebGL-capable device.

The host selectRig keeps the physical car root stable, copies paint/brake colour and wheel pose, rebinds wheels/materials/anchors, rebuilds the x-ray silhouette, invalidates dimensions and disposes the old owned GPU resources. The rig studio still borrows the actual vehicle. drive.rig-model stores model/loadout locally; it does not change campaign saves. New body factories must return the same contract and support the shared footprint; different handling/wheelbases need an explicit simulation adapter.

The splash keeps its live world, golden light, orbit and reel. Primary navigation is Rig, Drives, Surveys, The Line. Settings, sign-in and About live in a separate utility row. Navigation now uses native buttons, visible keyboard focus and 44px minimum utility targets. DRIVE is a 56px primary action, GPS Drive secondary. Settings offers Glass Brackets (default), Instrument Panel and Route Docket; selecting a treatment returns to the splash for comparison and stores drive.menu-treatment.

Validation: esbuild parses main/menu and bundles rig; TypeScript checks rig-model.ts and menu.ts. Six model/loadout combinations contain finite geometry and dispose owned resources exactly once. Twelve swaps using the actual selectRig function preserve position, paint and wheel articulation. DOM checks cover both account states, model/loadout selection, all three persistent treatments and DRIVE. The first DOM harness run had a misnamed views stub; corrected and rerun successfully. Live visual validation is blocked because the available cloud browser cannot create a WebGL context, including on the pre-change build. No mobile FPS claim is made.
